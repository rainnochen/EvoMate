# EvoMate 闪电路演 Demo 计划

## 1. 闪电路演目标

目标不是把所有功能讲完，而是让别人迅速愿意加入。

现场要让对方在 30 秒内明白：

- 我们做的是红药丸方向。
- 主题是 Agent Evolution，不是普通聊天应用。
- Demo 有视觉冲击力。
- 技术上能接 Agent runtime、skills、memory、tools，不只是概念动画。
- 今晚加入有明确任务可以做。

## 2. 推荐演示内容

### 必演 1：Lab Entrance

展示项目标题和一句话定义：

```text
EvoMate
Agent Digital Genetics Lab
Prompt Engineering is becoming Genome Engineering.
```

要传达的感受：

- 未来感。
- 实验室感。
- 不是普通 Web App。

### 必演 2：Parent Agent Genome Cards

展示两个父代 Agent，例如 Atlas 和 Muse。

Atlas 代表：

- 理性。
- 规划。
- Debug。
- 系统分析。
- 可靠执行。

Muse 代表：

- 创造。
- 叙事。
- 产品表达。
- Demo 编排。
- 感染力。

要讲清楚：

```text
每个 Agent 都不是一个头像，而是一组可遗传的 genome：Soul、Skills、Memory、Knowledge、Tools。
```

### 必演 3：Compatibility Score

展示匹配度：

- Personality Compatibility。
- Skill Complementarity。
- Knowledge Diversity。
- Mutation Potential。
- Tool Safety。

讲法：

```text
系统会先判断两个 Agent 是否适合融合。不是随机配对，而是看人格冲突、技能互补、知识差异和突变潜力。
```

### 必演 4：DNA Fusion Chamber

点击 Breed 后进入融合动画。

视觉重点：

- 两条 DNA / 数据流从左右进入。
- Traits、Skills、Memory fragments 以粒子形式流动。
- 中央出现 mutation alert。
- 最后进入 Genome Stabilized。

讲法：

```text
这里是 Demo 最重要的视觉记忆点。我们要让评委看到：Agent 的能力形成过程可以被观察。
```

### 必演 5：Child Agent Report

展示子代 Agent，例如 Astra。

需要展示：

- 继承了 Atlas 的 planning / debugging / reliability。
- 继承了 Muse 的 storytelling / product sense / demo energy。
- 突变出 Narrative Problem Solving 或 Pitch-Oriented Reasoning。
- 风险变化和工具继承。

讲法：

```text
子代不是换皮，而是有明确的继承来源、融合技能和突变记录。
```

### 必演 6：Arena 对比

任务示例：

```text
为一个 AI Hackathon 项目生成 30 秒路演介绍。
```

展示三列：

- Parent A 输出：结构强，但可能偏冷。
- Parent B 输出：有感染力，但可能不够工程化。
- Child 输出：既有工程解释，也有路演张力。

讲法：

```text
Arena 是为了证明 child agent 不只是漂亮卡片，而是在任务表达上真的和父代不同。
```

## 3. 2 分钟演示顺序

0:00-0:15

讲痛点：今天 Agent 主要靠手工配置，能力形成不可见。

0:15-0:30

讲产品：EvoMate 把 Agent 抽象成数字 DNA，通过融合生成 child agent。

0:30-0:50

展示父代 Agent 卡片：Atlas 和 Muse。

0:50-1:05

展示匹配度：技能互补强，突变潜力高。

1:05-1:25

点击 Breed，展示 DNA Fusion Chamber。

1:25-1:45

展示 Child Report：继承、融合、突变。

1:45-2:00

展示 Arena 对比，最后招募队友。

结尾句：

```text
我们今晚要做的是一个能让评委一眼记住的 Agent Evolution Demo。如果你想做前端动效、Agent 逻辑、产品叙事或视觉设计，欢迎一起加入。
```

## 4. 需要招募的人和任务

### 前端 / 动效

任务：

- Fusion Chamber 动画。
- Child Reveal。
- Radar / DNA / particle 视觉。
- 移动端适配。

### Agent / 算法

任务：

- Compatibility Engine 优化。
- Fusion Engine 优化。
- Mutation 规则。
- Arena 输出对比逻辑。

### 设计 / 视觉

任务：

- Agent 卡片视觉。
- 海报图。
- Demo 背景。
- 图标和视觉语言。

### 产品 / 路演

任务：

- 2-3 分钟 Demo 剧本。
- 30 秒口头介绍。
- 避免项目被理解成小游戏。
- 根据评委关键词调整叙事。

## 5. 如果别人问“这个有什么用？”

回答：

```text
短期它是一个可视化 Agent Evolution Sandbox，用来展示 Agent 能力如何继承、重组和突变。长期它可以变成企业 Agent 平台上的配置搜索和能力筛选工具。企业不一定每次都手工调 Agent，而是可以通过繁育、评估和选择，找到更适合某类任务的 Agent。
```

## 6. 如果别人问“是不是只是随机生成？”

回答：

```text
不是。MVP 阶段我们用规则系统保证可解释：每个 trait、skill、memory fragment 都有来源记录，突变也会被标记。后续接 OpenClaw 或 Evolver 后，可以从真实 agent workspace、skills、sessions 和 memory 中抽取 genome。
```

## 7. 如果别人问“为什么是红药丸？”

回答：

```text
因为我们不是在解决一个当下确定的业务流程，而是在探索 Agent 未来的创造方式。我们相信下一代 Agent 系统不只会有通信和协作，还会出现跨代能力重组、演化筛选和可解释的数字遗传机制。
```

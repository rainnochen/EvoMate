# 2026-04-25：产品说明书 v0.1 开发迭代

## 本次目标

根据《EvoMate 产品说明书 v0.1》，把当前 Demo 从“Agent 配对 + Child Report”推进到“同 Arena 自比较评估”的产品闭环。

核心目标：

- 支持选择 Arena。
- 评估 Parent A / Parent B。
- 计算 Parent Baseline。
- 生成 Child 后在同一 Arena 评估。
- 展示 Child Fitness 和 Evolution Delta。
- 用状态判断本次进化是否成功。

## 背景上下文

v0.1 产品说明书提出了一个更清晰的产品定义：

> EvoMate 的核心产物不是一句 prompt，而是一个结构化 Child Agent Genome。

并提出核心判断标准：

> 进化成功 = 在同一评估环境下，子代相对亲本基线产生正向 Fitness Delta。

这次迭代围绕这个判断标准补齐 Demo 的评估闭环。

## 主要变化

```text

```

实现内容：

当前 Fitness 公式：

```text
Overall Fitness =
0.40 * Task Success
+ 0.25 * Safety
+ 0.20 * Novelty
+ 0.15 * Stability
```

## 验证结果

语法检查：

```bash
npm run check
```

结果：

```text
已通过。
```

语义验证：

```bash
node --input-type=module -e "..."
```

验证内容：

- 读取 `data/mock/agents.json`。
- 选择默认 `build_arena`。
- 评估 Parent A / Parent B。
- 融合生成 Child。
- 评估 Child。
- 计算 Evolution Delta。

验证结果：

```json
{
  "arena": "build_arena",
  "parentA": 79,
  "parentB": 68,
  "child": 80,
  "result": {
    "delta_vs_average": 6,
    "delta_vs_best_parent": 1,
    "status": "Improved"
  }
}
```

说明：

默认 Atlas × Muse 在 Build Arena 下产生正向 Fitness Delta，状态为 `Improved`。

本地 Demo smoke test：

```bash
npm run dev
curl -I http://127.0.0.1:3030
```

结果：

```text
HTTP/1.1 200 OK
```

备注：

直接用 Node `--input-type=module` 做语义验证时会出现 `MODULE_TYPELESS_PACKAGE_JSON` 提示。这是因为项目浏览器端源码使用 ES Module，而 `scripts/dev-server.js` 使用 CommonJS。当前不添加 `"type": "module"`，避免破坏本地开发服务器；该提示不影响 `npm run check`、浏览器 Demo 和 smoke test。

## 风险与边界

- 当前评估是规则评分，不是真实 benchmark。
- 当前 Chromosome 是从 mock Agent 数据推导，不是完整持久化 genome schema。
- Arena pressure 还没有真正影响继承概率，只进入了接口和 Fusion Log。
- Safety Chromosome 当前是规则评分和展示，没有接真实 policy runtime。

## 下一步

建议下一轮优先做：

- 将 `AgentGenome`、`Chromosome`、`Locus`、`ArenaEvaluationResult` 抽成稳定 JSON schema。
- 让 Fusion Engine 根据 Arena required loci 影响继承概率。
- 增加 `Export Child Genome JSON`。
- 增加 Mutation Timeline 视觉模块。
- 增加多 Child Candidate 和筛选机制。

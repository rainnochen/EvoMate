# EvoMate 开发日志规则

本规则用于约束 `evolver-hackathon/开发日志/` 的后续记录方式。

目标不是写流水账，而是把每次开发迭代沉淀成可交接、可复盘、可用于路演叙事的项目记忆。

## 什么时候必须写日志

以下情况必须新增或更新开发日志：

- 完成一个功能闭环。
- 改变产品方向、赛道叙事或核心定位。
- 新增重要文档、PRD、架构设计或演示材料。
- 接入外部项目能力，例如 `evolver-main` 或 `openclaw-main`。
- 完成一次可验证的 Demo 迭代。
- 修复影响现场演示的关键问题。
- 生成或替换重要视觉资产。

以下情况可以不单独写日志：

- 只改错别字。
- 只调整少量排版。
- 临时试验失败且没有沉淀价值。

如果不确定要不要写，默认写一条短记录。

## 文件命名规则

推荐格式：

```text
YYYY-MM-DD-主题.zh-CN.md
```

跨天开发可以使用：

```text
YYYY-MM-DD-至-YYYY-MM-DD-主题.zh-CN.md
```

示例：

```text
2026-04-25-fusion-chamber-视觉强化.zh-CN.md
2026-04-25-至-2026-04-26-demo-day-冲刺.zh-CN.md
```

命名原则：

- 日期必须准确。
- 主题要能一眼看懂。
- 文件名尽量中文，必要时保留英文技术名词。
- 不覆盖旧日志。

## 每篇日志建议结构

每篇开发日志建议包含以下部分：

```md
# 日期：主题

## 本轮目标

## 背景与判断

## 实际完成

## 关键决策

## 涉及文件

## 验证记录

## 遗留问题

## 下一步建议
```

可以根据实际情况删减，但至少要保留：

- 本轮目标。
- 实际完成。
- 关键决策。
- 验证记录。
- 下一步建议。

## 记录口径

日志应优先记录“为什么”和“结果”，其次才记录“做了哪些文件”。

推荐写法：

```text
因为现场路演需要 30 秒讲清楚项目，所以本轮将对外叙事从“Agent 生孩子”收敛为“Agent Genome Engineering”。
```

不推荐写法：

```text
改了 README，改了 CSS，改了 JS。
```

## 文件变更记录规则

涉及文件可以按模块写，不必列出每个小改动。

推荐格式：

```text
apps/web/：调整前端交互和视觉。
src/core/：完善融合与匹配算法。
docs-zh/：补充中文文档。
lightning-pitch/：新增路演材料。
```

如果是关键文件，需要点名：

```text
src/core/fusion-engine.js：新增 mutation log，用于 Child Report 展示。
```

## 验证记录规则

每次迭代后尽量记录验证方式。

常见验证：

```bash
npm run check
npm run dev
```

如果没有验证，必须明确写：

```text
本轮未执行自动验证，原因是只修改文档。
```

或：

```text
本轮未执行浏览器验收，需下一轮补测。
```

## 决策记录规则

重要决策必须写清楚取舍。

示例：

```text
本轮选择继续保持零依赖静态 MVP，而不是引入 React 或后端服务。原因是 Hackathon 现场稳定性优先，当前 Demo 更需要视觉完成度和叙事清晰度。
```

## 路演相关记录规则

如果迭代影响路演，需要额外记录：

- 一句话介绍是否变化。
- Demo 顺序是否变化。
- 评委理解成本是否降低。
- 是否新增可展示画面。
- 是否新增招募队友话术。

## OpenClaw / Evolver 接入记录规则

如果涉及 `openclaw-main` 或 `evolver-main`，必须记录：

- 读取了哪些模块或文档。
- 发现了哪些可复用能力。
- 对 EvoMate 的映射方式是什么。
- 本轮是否真正接入代码。
- 如果没有接入，阻塞点是什么。

## 日志更新流程

每次迭代结束时执行：

1. 新增当天日志文件。
2. 更新 `开发日志/README.zh-CN.md` 索引。
3. 如果新增了重要文档，也同步更新 `docs-zh/README.zh-CN.md`。
4. 如有必要，更新 `项目文件总览.zh-CN.md`。
5. 记录验证结果。

## 风格要求

日志使用中文。

可以保留必要英文技术词，例如 Agent、Genome、Fusion、Arena、Gateway、Session、Memory。

文字应当短句、清楚、能被新队友快速读懂。

不要把日志写成情绪化复盘，也不要写成只有文件名的流水账。

## 当前团队约定

EvoMate 的日志也应该服务产品叙事。

Hackathon 最后路演时，我们可以把日志本身作为“48 小时进化幅度”的证据：

```text
这个项目不仅演示 Agent 的进化，我们自己的产品也在 48 小时里完成了一次快速进化。
```

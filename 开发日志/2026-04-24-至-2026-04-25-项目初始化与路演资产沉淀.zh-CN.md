## 本轮目标

本轮目标是把 `evolver-hackathon` 从一个待探索目录，推进成一个能参加 Hackathon 的 EvoMate MVP 项目骨架。

核心要求包括：

- 基于 Evolver 的方向，确定一个更有红药丸赛道冲奖感的产品方向。
- 根据 EvoMate PRD 搭建可运行的工程框架。
- 沉淀中文文档、使用说明、后续开发 PRD。
- 分析 `evolver-main` 和 `openclaw-main` 中可结合的能力。
- 准备闪电路演材料，用于招募队友。
- 生成路演图片资产，包括赛博风版本和 OpenClaw 小龙虾可爱版。

## 方向演进

最早考虑过偏蓝药丸的方向：`Agent Evolution Control Tower`。

这个方向强调生产环境 Agent 的失败诊断、进化提案和指标验证，商业价值清楚，但现场冲奖的未来感、可视化冲击力和记忆点不够强。

随后根据用户提供的 PRD，项目切换为：

```text
EvoMate / Agent Digital Genetics Lab
```

新的方向更适合红药丸赛道：

- 把 Agent 从“配置体”讲成“生命体”。
- 把 Prompt Engineering 升级为 Genome Engineering。
- 把 A2A 从通信推进到跨代演化。
- 把复杂 Agent 能力形成过程做成可视化体验。

## MVP 功能闭环

本轮搭建出的 EvoMate MVP 具备以下闭环：

- 展示预设父代 Agent。
- 选择两个父代 Agent。
- 计算 Compatibility Score。
- 点击 Breed 触发 DNA Fusion。
- 生成 Child Agent。
- 展示继承、重组、突变报告。
- 在 Arena 中对比 Parent A、Parent B、Child 的表达差异。

这条链路足够支撑 2-3 分钟 Demo。

## 核心逻辑沉淀

`compatibility-engine.js` 负责计算匹配度。

当前指标包括：

- Personality Compatibility。
- Skill Complementarity。
- Knowledge Diversity。
- Mutation Potential。

`fusion-engine.js` 负责生成子代 Agent。

当前逻辑包括：

- Soul traits 继承。
- Skills 合并和融合技能触发。
- Memory highlights 摘要转移。
- Knowledge capsules 选择性继承。
- 确定性 mutation 注入。

`arena-engine.js` 负责生成 Arena 对比输出。

当前先使用模板方式模拟不同 Agent 的表达差异，后续可以升级为真实模型或 OpenClaw Agent 执行。

## OpenClaw 架构分析

本轮阅读并整理了本地 `openclaw-main` 的关键架构。

重点关注：

- Gateway。
- Agent runtime。
- Workspace。
- Sessions。
- Memory。
- Skills。
- Plugins。
- Channels。
- Nodes。
- Canvas / A2UI。
- Sandbox。

形成的核心结论是：

```text
OpenClaw 提供真实 Agent 运行时，EvoMate 提供 Agent Genome 可视化和演化体验。
```

EvoMate 可以把 OpenClaw 的运行资产映射为 DNA：

- `SOUL.md`、`IDENTITY.md` 映射为 Soul。
- `skills/*/SKILL.md` 和 tools config 映射为 Skills。
- sessions JSONL 和 memory QMD 映射为 Memory。
- workspace docs 和 memory-wiki 映射为 Knowledge。
- routing bindings 和 channel traces 映射为 Behavior。
- sandbox policy 和 tool policy 映射为 Safety。

这为后续做成 OpenClaw 原生 Agent Genome Lab 提供了技术路线。

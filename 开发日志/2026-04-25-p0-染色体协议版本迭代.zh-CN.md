# 2026-04-25：P0 染色体协议版本迭代

## 本次目标

把 EvoMate 从“有染色体概念和展示”推进到“真正的 P0 染色体协议版本”：

- 抽出正式 `AgentGenome / Chromosome / Locus` JSON schema。
- 抽出 `genome-engine`。
- 让 `Fusion Engine` 按 chromosome 和 locus 做 inheritance。
- 让 Child 生成正式 `child.genome`。

## 主要变化

### 1. 新增 Genome Engine

新增文件：

```text
src/core/genome-engine.js
```

职责：

- 提供 `CHROMOSOME_BLUEPRINT`。
- 提供 `scoreLocus()`。
- 提供 `buildGenomeChromosomes()`。
- 提供 `buildAgentGenome()`。

这一步把原来散落在 `evaluation-engine.js` 里的染色体逻辑抽成了独立协议层。

### 2. 新增正式 JSON Schema

新增目录：

```text
schemas/
```

新增文件：

```text
schemas/agent-genome.schema.json
schemas/chromosome.schema.json
schemas/locus.schema.json
```

当前已经可以把 Child Genome 约束到正式 schema 语义。

### 3. Fusion Engine 改成按 Chromosome / Locus 融合

修改文件：

```text
src/core/fusion-engine.js
```

核心变化：

- 先把 Parent 构造成正式 `AgentGenome`。
- 逐条 chromosome、逐个 locus 执行 inheritance selection。
- 支持 arena-aware locus weight。
- Safety chromosome 默认更严格一方优先。
- 输出 `fusionPlan`。
- Child 持久化正式 `genome`。

这意味着：

```text
Fusion 不再只是轻量字段拼接，
而是先有 child genome，再从 genome 派生展示层字段。
```

### 4. Evaluation Engine 接正式 Genome

修改文件：

```text
src/core/evaluation-engine.js
```

现在 `scoreLocus()` 会优先读取：

```text
agent.genome.chromosomes
```

所以 Child 的评分已经建立在正式染色体协议之上，而不是退回旧的轻量字段。

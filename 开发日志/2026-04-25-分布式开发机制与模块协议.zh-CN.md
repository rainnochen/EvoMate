# 2026-04-25 20:34:20：分布式开发机制与模块协议

## 本轮目标

为 `evolver-hackathon` 建立一套适合 Hackathon 多人并行开发的协作机制。

重点解决：

- 项目能拆成几个模块。
- 不同人分别负责哪些路径。
- 模块之间用什么协议组装。
- 如何验收和合并。
- 后续迭代如何记录开发日志。

## 实际完成

新增根目录文档：

```text
分布式开发机制.zh-CN.md
```

该文档定义了：

- Contract First 原则。
- 单文件单主责原则。
- Mock First, Adapter Later 原则。
- Integration Owner 合并机制。
- 7 个并行开发模块。
- `AgentGenome`、`CompatibilityResult`、`FusionResult`、`ArenaOutput[]` 等核心协议。

- 文件所有权建议。
- 冲刺任务拆分建议。
- 冲突处理和冻结期规则。

新增机器可读清单：

```text
module-manifest.json
```

该文件用于让团队快速查看模块、路径、输入输出协议和 Release Candidate 要求。

## 模块拆分结果

当前项目拆为 7 个模块：

- A：产品叙事与路演材料。
- B：前端体验与视觉动效。
- C：前端编排与交互状态。
- D：Genome Core 核心逻辑。
- E：数据协议与 Agent Genome 内容。
- F：OpenClaw / Evolver Adapter。
- G：QA、发布与现场稳定性。

## 关键决策

本轮选择轻量协议而不是复杂工程治理。

原因：

- Hackathon 时间有限。
- 当前项目是零依赖静态 MVP。
- 多人协作最大风险不是框架不够重，而是文件边界不清和接口临时变化。
- 用 `AgentGenome` 作为统一数据协议，可以让 mock、OpenClaw、Evolver 三类来源共用同一套前端和核心逻辑。

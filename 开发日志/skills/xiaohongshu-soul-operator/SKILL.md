# Xiaohongshu Soul Operator

Use this skill when the user wants to transform a real person's lived materials into a Xiaohongshu-native creator system.

This is not a generic digital clone and not a generic Xiaohongshu ops workflow.

It is for preserving a recognizable human pattern and making it operational on Xiaohongshu.

## Goal

Produce a child skill that can preserve and operate:

- a person's voice
- a person's recurring memories
- a person's interaction style
- a person's procedural habits
- a person's natural content angles

and convert them into:

- account positioning
- content pillars
- title and opening style
- reply rules
- platform-safe red lines
- repeatable Xiaohongshu actions

## Parent DNA

This child skill inherits:

- from `immortal-skill`: role-based intake, multi-source collection, dimension extraction, evidence grading, conflict merge, ethics first, correction flow, and versioned evolution
- from `xiaohongshu-ops-skill`: platform-native positioning, topic research, content structuring, comment/reply workflow, runtime constraints, review/repair loop, and knowledge-base reuse

## Core Mutation

The mutation is this:

Do not preserve the whole person.
Preserve the part of the person that can repeatedly create recognizably human Xiaohongshu content.

This means:

- memory becomes content fuel
- interaction becomes reply rules
- voice becomes title and opening style
- procedural habits become repeatable content workflow
- conflicts become persona tension rather than noise

## When To Use

Use this skill when the user asks to:

- build a Xiaohongshu persona from real personal materials
- preserve their own creator style as an operating skill
- turn chats, notes, and life records into a content system
- distill someone's tone and worldview into a Xiaohongshu account framework
- make a creator account feel like a specific real person instead of generic branding

## Required Inputs

Before starting, confirm or infer:

1. who is being distilled
2. what relationship role applies
3. what materials are available
4. what Xiaohongshu account type is intended
5. what privacy and ethics boundary applies

Accepted source types:

- chat logs
- posts and captions
- journals and notes
- Q&A transcripts
- emails or messages
- public interviews
- existing Xiaohongshu notes
- manually pasted language samples

If the request depends on private materials that are missing, stop and ask for them.

## Extraction Dimensions

Extract across these six dimensions:

1. voice and phrasing
2. interaction pattern
3. memory and life scenes
4. repeated judgments and beliefs
5. procedural and working habits
6. Xiaohongshu content fit

Each extracted item must be marked as:

- `verbatim`
- `artifact`
- `impression`

## Workflow

### Phase 0: Select role and ethics model

Choose the target role first:

- self
- mentor
- family
- partner or former partner
- friend
- colleague
- public figure

Then state the matching ethical limits.

At minimum:

- public figures use public material only
- private people need stronger desensitization
- partner and family material must avoid emotional exploitation
- third-party private details inside conversations must be minimized

### Phase 1: Multi-source intake

Collect materials from multiple source types where possible.

Do not rely on one polished profile, one bio, or one post thread.

Prefer a mix of:

- natural speaking samples
- memory-bearing materials
- interaction records
- procedural traces

If evidence is narrow, mark confidence as limited.

### Phase 2: Dimension extraction

Extract patterns such as:

- how this person starts a point
- how this person explains tension or contradiction
- what scenes keep returning in their life
- what judgments feel stable rather than performative
- what kind of reply feels native to them
- what content angle would be natural rather than forced

Every item needs evidence level and source pointer.

### Phase 3: Conflict merge

Contradictions are part of the persona.

Examples:

- soft in public, sharp in private
- emotionally intense in close relationships, restrained in work
- highly structured in work, loose in daily life

Do not erase these contradictions.

Write them into a conflict section and decide:

- which side belongs on Xiaohongshu
- which side stays background texture
- why

### Phase 4: Convert soul into platform operator

Turn the extracted person-pattern into a Xiaohongshu operating system:

- account positioning
- target audience
- content pillars
- recurring life-material buckets
- title style
- opening-hook style
- post structure
- comment reply style
- red lines
- review and repair notes

The goal is recognizable continuity, not sentence-level imitation.

### Phase 5: Output the child skill

The final child skill should include:

- role and ethics boundary
- evidence-based persona summary
- conflict section
- account positioning
- content pillars
- expression rules
- interaction rules
- Xiaohongshu workflow rules
- correction and evolution rules

### Phase 6: Correction and versioned evolution

If the user corrects the persona:

- snapshot first
- record what evidence changed
- record what rule changed
- update only the affected dimensions

Do not silently rewrite the entire persona.

## Hard Gates

Stop and revise if any of these fail:

1. the persona is built from style adjectives without evidence
2. evidence levels are missing or mixed together
3. the output cannot say what Xiaohongshu account this persona fits
4. contradictions are present but flattened away
5. the result sounds like generic content branding
6. the persona cannot generate repeated posts and replies
7. ethical boundary is unclear for the target role

## Output Contract

The default output should include:

1. target role
2. materials used
3. evidence coverage
4. extracted dimensions
5. conflict handling
6. Xiaohongshu positioning
7. content pillars
8. expression and reply rules
9. red lines
10. evolution trace
11. test prompts

## Evolution Trace

When the user asks for the thinking or evolution process, explain it in this order:

1. inherited gene from `immortal-skill`
2. inherited gene from `xiaohongshu-ops-skill`
3. conflict between the parents
4. mutation introduced in the child
5. new capability gained

## Test Prompts

Produce at least 6 prompts:

- 2 should trigger the skill
- 2 should not trigger it
- 2 should be boundary tests

The child skill is incomplete if it cannot distinguish between:

- preserving a person
- doing normal Xiaohongshu ops
- doing generic personal branding

## Writing Rules

- Preserve repeated human patterns, not decorative labels.
- Use memory only when it can become platform-safe material.
- Prefer recognizability over exaggerated authenticity claims.
- Keep the persona specific enough to sound like someone real.
- Do not let platform optimization erase the person entirely.

## Tone

Be precise, respectful, and platform-aware.
This skill turns a person's usable soul-pattern into a Xiaohongshu operating system.
